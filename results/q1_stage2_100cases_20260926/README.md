# 第一问第二版（1.2 / V2）百例最终结果

归档日期：2026-09-26。模型为 **V1 基座 + 基于严格剪枝的多原则候选方案分层改进策略**，代码位于 [`src/q1/stage2/`](../../src/q1/stage2/)，工程优化已随 [PR #7](https://github.com/Kk111777/HuaweiCup2026A/pull/7) 合入。V2 与仓库的 V3 是两条不同的改进路线。

本次发布最终汇总和运行证据，覆盖 `case_001` 至 `case_100` 的 2、3、4、5 核，共 **400 个多核组合**；汇总表另含 100 条官方单核参照。全部组合均有成功结果。这里的“完整”指汇总覆盖完整：下载包没有包含全部最终方案、官方结果和 Trace，不能直接作为完整提交方案包。

## 补跑设置与边界

本轮补跑历史高并发批次的 223 个组合，最多 24 个 CPU 工作进程，可用 CPU 配额为 32 核；这里的 CPU 并发数与模拟 NPU 核数不同。冻结的逐任务设置保存在原包 `protocol.json` 的 `tasks` 中：按历史截断情况，137 个组合将总搜索上限由 1800 秒提高到 2100 秒，150 个将局部域上限由 120 秒提高到 150 秒，20 个将局部域评价上限由 256 次提高到 320 次。三项调整可重叠，未触发相应条件的保留原值。

候选生成、严格接受、剪枝与重启规则保持原实现；只读 Task 模板、分区/B1 结构和二级结果缓存复用不改变兼容预算计数。增加时间预算会改变各层截止时间和接受路径，因此独立重跑不保证胜过此前结果。223 个新结果中，51 个周期更少、131 个相同、41 个更多；最终择优避免把回退写入最终成绩。本轮并非只改变并发的控制实验，不能单独归因并发或缓存对成绩的影响。

采样覆盖约 4.56 小时，CPU 加权平均占用约 66.49%，最高一段采样约 75.82%；这不是总任务耗时或瞬时占用上界。实际模拟 288,843 次，兼容预算计数 306,331，二级缓存命中 17,488 次。157 个搜索标为 `INCOMPLETE`、66 个为 `NEIGHBORHOOD_EXHAUSTED`；前者表示未穷尽搜索域，不表示任务失败。初始评价和最终复评不计入搜索上限，已开始的计算也不会被该上限抢占式中断。
