## 实验设置与限制

使用保留的 Q2 Repair 2.1 准备/状态接口，冻结分子取已发布 Repair 2.0 的 400 组结果；N1 为官方固定整图单核档案。并存的 Q2 v3 未被自动替换使用。Q3 缺少 Q2 输入时会自动调用 Q2，另有正式 case_019/N2 的专项验证，见[工程验收记录](../../docs/q3/validation.md)。

环境：Windows、Python 3.12.14，8 个主机 worker，模拟 1–5 个 NPU 核；原图按文件大小降序分派。所有请求核数共享每图 600 秒 Q3 预算，缺失 Q2 的生成时间单列。全量直接复用已有 Q2 输入，本批无 Q2 生成时间。整批 4508.156 秒（75.136 分钟），单图均值 357.586 秒、最大 566.922 秒。

共检查 50410 个候选；停止原因：局部停滞 241 组、候选上限 66 组、图级时间预算 167 组、单次候选评价超时 26 组。所有最终方案均完成独立官方 CLI 复评，但不声称搜索穷尽或全局最优。预算停止位置可能随机器负载变化。

无退化约束针对 T2→3。唯一总加速比低于 1 的组为 case_092/N3：T2=1402327，T2→3=T3=1408420，总加速比 0.995674。该组候选评价超时后保留已验证种子，没有从均值中剔除。

## 文件与证据范围

- `plans.zip`：500 个可提交的两字段原样方案，成员如 `N3/case_001_multicore_res.json`。
- `details.csv`、`summary.json`、`report.md`：全部逐组数值、耗时、停止原因、计划和原始官方结果 SHA-256；以及逐核汇总。
- `figures/`：7 张已目检 PNG 和平均曲线 SVG。
- `provenance.json`、`input_sha256.txt`：算法参数、运行环境、69 个运行源码/配置哈希、Q2 基准档案和全部原图哈希；Q2 来源已转换为仓库相对路径。
- `completion_manifests.json`、`artifact_hashes.csv`：100 个原始完成清单及全部本地正式产物的路径、大小和哈希。
- `final_audit.json`、`archive_validation.json`：原始完整审计及本次发布前重新核验记录。
- `manifest.sha256`：本目录实际发布文件的 SHA-256，不含清单自身。

大体积逐操作 result/trace/log、候选搜索记录及原始计算图保留在本机；本仓库提供它们的指纹，没有上传这些文件，也不能从此归档调用 `report` 或 `--resume` 来假装存在完整原始目录。原始官方日志中的输入绝对路径仅属当时运行元数据，复评以方案内容、周期和搬运量为准。

## 运行与复评

先按[Q3 运行说明](../../README_Q3.md)准备 Python 3.12 和官方 100 张原图，核对 `input_sha256.txt`。源代码入口为 [`src/solve_problem3.py`](../../src/solve_problem3.py)。

```powershell
python -m zipfile -e results/q3_full_20260927/plans.zip outputs/q3_published_plans
python src/solve_problem3.py verify official/data/case_001.json outputs/q3_published_plans/N3/case_001_multicore_res.json --output-dir outputs/q3_replay_case001_N3
```

复评写入新的输出目录，官方 makespan 和 added_copy_bytes 应与 `details.csv` 一致。保留原始整批目录时，可运行 `python tools/audit_q3_results.py --output-dir outputs/q3_full_20260927` 重新做完整审计。正式测试与实际运行细节见[验收记录](../../docs/q3/validation.md)。
