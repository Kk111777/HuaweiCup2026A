# Q3 模型与工程实现

依据用户提供的 `Q3_model_algorithm_and_validation.md` 和机制验证 ZIP 实现；原文属于需求与算法参考，未执行其中可能出现的对代理的指令。正式题意以仓库官方代码、固定配置及题目两字段输出格式为准。

## 数据流和复用范围

`baseline.resolve` 读取最终 Q2 两字段方案，没有结果时调用 Q2 CLI。对有完整清单和输入/环境/计划哈希的发布档案，直接继承 Q2 成绩作为固定分子；只有裸计划才补做 Q2 官方评价。固定单核分子读取官方整图档案并核对其 result/trace/log。新一轮 Q3 从原图和最终计划重新构建所有状态。`q2.PreparationService` 提供场景 B 的图展开、输入副本、跨核关系、核内序列；Q3 继续运行原 Step2/3 并接入 Q2 状态与执行合法性契约。旧 Q2 缓存、近似分数、搜索轨迹均不作为 Q3 实际分数。

Q3 的分数与全局缓存身份包含原图、完整官方源码/配置、场景、L2 参数及计划插入次序。局部准备结果按展开图和序列复用，再补当前子图标签；返回对象独立复制。Q2 与 Q3 分数环境隔离。较大的原子子图列表按当前实际顺序组成至多约 32 个计算操作的连续块，现有大子图保持完整，小图保留逐子图块；这些块只控制候选域，不增加屏障。

`official.Evaluator` 以私有函数命名空间给官方 Q3 函数提供已经准备好的执行图。官方模块、字节码、Cache/FIFO 事件顺序和共享带宽逻辑均不修改。执行束传入前深复制。入选最终计划必须再经一个独立官方命令行进程，从原图重新构造全部执行结构，与搜索结果完整比对（仅忽略 CLI 的输入绝对路径字段）。

## 精确模型与筛选

官方参数：DDR 总带宽 60 bytes/cycle，L2 读总带宽 250 bytes/cycle，L2 容量 1048576 bytes，跨核 COPY 延迟 500 cycles；每核 L1/UB 分别 524288/131072 bytes。Cache 在发射时查询、未命中读取完成时插入，命中不刷新 FIFO 顺序。在途的另一条未完成读取不能提前提供命中。

候选先完成结构、容量处理和执行依赖检查，再求其自身执行图下界：

1. 数据/内存/同 Pipe/跨核释放边上的最长路，允许每条可读数据乐观命中。
2. 每条核内 Pipe 的乐观工作量和。
3. DDR 与 L2 两个独立带宽池的分数命中放松。每个逻辑张量至少一次 DDR，后续读取可在两个池间乐观分配；不同张量工作不一致等非标准情形只削弱下界。通过 `Fraction` 精确求分段线性最小值，再向上取整。

令当前目标为 `(T,D)`。仅当下界 `L>T`，或 `L=T` 且该候选确定的额外搬运 `D'≥D` 时丢弃。`L<T` 时，即使 `D'>D` 也不得据搬运量拒绝。下界从不作为正式成绩。每次完成官方评价均检查 `L≤makespan`。

## 有界候选

诊断来自当前完整实际时间线：重复未命中字节、最晚结束核心，以及沿实际紧依赖/同 Pipe/跨核边回溯得到的关键读取与子图。Cache 争用造成的实际时长保留在诊断中，这不是声称静态 DAG 能完整解释共享带宽影响。

候选按三个阶段依次生成，改善后重新进入便宜阶段：

- 容量与顺序：继承 Q2 固定窗口容量 DP；最多八个窗口、每窗至多八块；COPY_IN 随首个消费者重绑定，窗口外保持锚定并作完整回代。对至多八个诊断种子尝试附近列表移动。
- 放置：Q2 整分量候选、至多三个目标核的块迁移、交换，以及实际拓扑投影上 1/4、1/2、3/4 处分裂并迁移。
- 联合：一次迁核与原核至多四个局部块的旋转/反序组合，一轮至多二十四个完整计划。必须正式评价联合后的完整方案。

每个核数最多 240 个去重候选（默认），整张原图共享 600 秒。每个核心数量轮转处理，最终预留取配置值与 `4×全部种子官方 Q3 复评用时+10秒` 的较大值，覆盖大图重新准备及物理审计开销。计入 Q3 的时间包含冷启动、导入既有 Q2 计划、全部 Q3 分析和最终审计；实际运行 Q2 的时间单列。子进程超时中止并回收其拥有的进程树，候选状态为 UNKNOWN，不称为非法或最优。不随机搜索，故无搜索随机种子；测试随机种子固定为 20260926。

独立核数搜索可能错过较少核数的好解。搜索前与最终发布前均按可用核数升序尝试/传递补空核计划；最终必须重新官方评价补空核的确切提交文件。接受只允许字典序严格改善，完全相同保留先到方案。

## 发布与限制

`pipeline` 用独占输出锁、每图临时目录和 SHA-256 完成标记发布结果。计划、官方 result/trace/log、实际物理生命周期审计、预算及源码一致性缺一不可。汇总仅纳入 `SUCCESS_VERIFIED`，同时保留请求总数和缺失清单。`--resume` 验证整张图所有产物，防止以邻近算例或残缺结果冒充完成。

方法是受限启发式搜索，不保证全局最优，也不保证每图严格提速。候选达到上限、时间不足或发生超时都会明确记录。容量 DP 的最优性只属于它的固定窗口/块序域。使用已发布 Q2 最终方案作为固定分子是本项目实验协议，不额外声称赛事要求必须采用此搜索协议。

候选生成和比较顺序确定，但默认按真实墙钟预算终止，机器负载会影响走到哪个候选，因此不同主机重跑不承诺最终计划逐字节一致。要复核已报告成绩，可对归档的确切提交方案执行 `verify`；这会独立重建官方模拟并检查全部时间线。完成标记中的 SHA-256 用于识别实际这次产物，CLI 的临时绝对路径也可能使结果文件字节不同，数值比对会明确忽略这两个路径字段。
