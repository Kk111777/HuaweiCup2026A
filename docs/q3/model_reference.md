# 题设、输入输出与评价口径

## 输入及可决定的变量

输入为原始操作—张量有向无环图、固定硬件配置、可用核数 $N\in\{1,2,3,4,5\}$，以及第二问对应核数的最终方案。按此前提出的保守继承边界，仅从第二问读取最终方案及报告所需的最终成绩，不导入旧搜索过程、候选序列、旧执行时间线、旧参数轨迹或旧内存分析。第三问的分析均由原图和最终方案重新计算，并计入第三问的计算预算。这里采用的是项目的保守实现约定，不将其误写为已经查证的新增赛事条款。

记可划分的非 `COPY_IN/COPY_OUT` 操作为 $V$。方案为
\[
 P=(\mathcal S,k,\pi),
\]
其中 $\mathcal S=\{S_1,\ldots,S_m\}$ 是 $V$ 的划分，$k(S_i)$ 是子图所属核心，$\pi_k$ 是核心 $k$ 上的子图列表。

提交 JSON 仍然仅有两个字段：`node_to_subgraph` 和 `core_schedules`。不增加操作、不改动操作周期、不增加重计算、不提交开始时间、不插入空等操作，不改变 Cache 替换规则。算法只能通过合法的子图划分、分核及列表顺序，间接改变实际读取时刻。[R1,R2]

同核所有子图合为一个 Task。**子图列表不是“前一子图全部完成后才能执行后一子图”的额外屏障。** 它影响官方核内序列和各 Pipe 的投影；不同 Pipe 上仍按官方依赖关系重叠执行。搜索用的“计算块”只是若干连续子图的组合，不是额外 Task，也不是硬件屏障。

## 固定参数

| 资源或延迟 | 固定值 |
|:--|--:|
| 每核 L1 | 524288 bytes |
| 每核 UB | 131072 bytes |
| 共享 DDR 总带宽 | 60 bytes/cycle |
| 场景 B 跨核 COPY 同步延迟 | 500 cycles |
| 共享只读 L2 容量 | 1048576 bytes |
| 共享 L2 读带宽 | 250 bytes/cycle |

每核有 `PIPE_MTE2`、`PIPE_MTE3`、`PIPE_M`、`PIPE_V` 四条 Pipe；每条同时最多运行一个操作。L2 与 DDR 分别共享各自的带宽，不能把它们合并成 310 bytes/cycle 的统一通路。[R2,R5]

## 三类指标必须分开

正式优化目标采用
\[
 F(P)=\bigl(T_3(P),D_{\rm add}(P)\bigr),
 \qquad\text{按字典序最小化。}
\]
即先减小官方 Makespan；时间相同再减小官方额外搬运量；完全相同保留先到方案。Cache 命中率是解释性指标，不替代 Makespan。

官方程序当前返回的搬运字段为
\[
 D_{\rm sched}=D_{\rm base}+D_{\rm spill},\qquad
 D_{\rm add}=D_{\rm sched}-D_{\rm original}.
\]
这些量在全局 L2 模拟之前由展开后的 COPY 和换入换出操作统计。**对同一方案，Q2 与 Q3 的该字段相同；不能自行从 `added_copy_bytes` 中扣除命中字节后仍称其为官方指标。**[R2]

另记实际走 DDR 的传输量为 $D_{\rm DDR}$，可由实际访问路径单独计算。对于本题常规的单输入、单输出搬运，
\[
 D_{\rm DDR}=D_{\rm sched}-H,
\]
其中 $H$ 为命中字节数。一般接口下应逐条汇总实际 DDR 路径，避免把 Cache 统计用字节与操作实际工作量混为一谈。

字节命中率为
\[
 \eta(P)=\frac{H(P)}{H(P)+M(P)},
\]
分母为零时按官方程序记为零。这里 $M(P)$ 为可查询 Cache 的未命中字节数，不是“未命中次数”。

对于用例 $i$ 和相同核数 $N$，令 $P^0_{i,N}$ 为冻结的第二问最终方案，$P^*_{i,N}$ 为第三问最终方案，记录
\[
 T_2=T_2(P^0_{i,N}),\quad
 T_{2\to3}=T_3(P^0_{i,N}),\quad
 T_3^*=T_3(P^*_{i,N}).
\]
分别报告硬件配置变化、额外算法改进及总加速比：
\[
 S_{\rm hardware}=\frac{T_2}{T_{2\to3}},\quad
 S_{\rm algorithm}=\frac{T_{2\to3}}{T_3^*},\quad
 S_{\rm total}=\frac{T_2}{T_3^*}.
\]
平均值应逐用例计算比值后作算术平均，不能用总时间之比替代。1 核的无 L2 分母沿用题目指定的固定基准；有 L2 的 1 核时间必须实际评价，不能强制把第三问 1 核加速比设为 1。[R1]

# 对官方实现的关键核对

## 命中在发射时决定，未完成的读取不能提供命中

COPY_IN 发射时查询逻辑张量标识；命中进入 L2 读通路，未命中进入 DDR 通路。一个未命中的读取已经开始，不表示数据已经进入 L2。若其他核心也在首个读取完成前发射相同张量的读取，它们仍分别未命中，官方程序没有把这些在途请求合并。[R2]

因此，“多个核心尽量同时读同一输入”不是一般的好规则。候选可以尝试让一个实际读取先完成，再让其他读取发生，但必须通过已有工作的合法调序实现。只把某个计算节点放到列表后面，不一定推迟其 COPY_IN：搬运 Pipe 可能提前运行，所以必须检查重建后的实际读取时刻。

## L2 不只可能复用原始图输入

Cache 查询针对最终执行图中的 COPY_IN。第二问的缓存换入也以 COPY_IN 表示，新物理张量保留原逻辑张量标识。因此，部分换入操作和跨核中间数据读取也可能命中 L2；不能只统计原图输入的出度。[R2,R5]

相同原始 DDR 来源不必然等于相同查询键。分析必须沿用评估器从 COPY_IN 的片上输出取得的逻辑标识，尤其不能把不同核心的物理编号或换入后的新编号直接当作不同数据。

## FIFO 不是最近使用优先

命中不会把驻留项移动到队尾。一个张量刚刚被命中，仍可能因为它很早进入 L2 而马上被淘汰。容量按字节计算，不能只限制驻留张量个数；超过 L2 容量的张量不插入。[R2]

还需保留一个源码细节：当前 `retire` 对每个完成的 COPY_IN 都调用插入过程，不只处理未命中读取。若该键仍在 L2，插入不做任何事；若一次已命中的在途读取尚未结束，原驻留项已被其他插入淘汰，则该读取完成时可以重新插入。预测或重新模拟时应与这段实现一致，不擅自改成只在未命中完成时处理插入。

## L2 命中不取消其他约束

命中仍占用本核的 MTE2；仍需申请本核 L1/UB；仍服从 Pipe 队列和数据、内存复用依赖。跨核 COPY_IN 即使命中，也必须等待对应 COPY_OUT 实际完成再加 500 cycles。它不是任意时刻都能从 L2 提前取出的数据。[R2,R5]

## Q3 全局执行沿用 Step3 的内存依赖

Step3 在无 L2 的核内参考模型下确定 Pipe 顺序，并把容量复用关系加入操作依赖图。Q3 的全局模拟沿用这些关系，而不是随意重新排序，也不能人为再加入一个“所有 Pipe 统一按原分配序串行发射”的限制。额外加入这种限制会缩小题目允许的并行空间。[R5]

官方 `memory_peak_by_core` 取自核内 Step3 结果，不能直接宣称它是全局 L2 时间线上重新计算的精确峰值。验证真实全局占用时，应从物理张量生产者的开始时刻和最后消费者的完成时刻重新统计；本次另做了这一检查。

# 第二问组件的保留与边界

| 第二问组件 | 第三问的处理 | 可以严格声称的性质 |
|:--|:--|:--|
| 图索引、操作依赖、场景 B 图展开 | 原样共享 | 同一合法方案的结构语义不变 |
| 当前分核、实际 Step1、块状态重建 | 保留；每次修改后重建 | 防止使用过期归属和过期顺序 |
| Step2/Step3 与全局执行环检查 | 原样共享 | 私有容量及固定执行依赖得到检查 |
| 闭区间驻留分析、容量窗口 DP | 保留原目标和适用条件 | 固定域内容量可行、最小扰动；不等于时间最优 |
| 整计算分量同核候选 | 保留为候选，不强制采用 | 消除该分量的计算中间产物跨核 COPY |
| 严格下界、重复结果复用 | 扩展为 Q3 独立评价条件 | 不误删所检查域中的可改进方案，不混用 Q2/Q3 分数 |
| 构造器与粒度参数 $\beta$ | 用于缺少初值或局部重构 | 候选生成规则，不是参数单调性定理 |
| 正式指标择优、最终重新评估 | 保留 | 最终方案不劣于已验证初值 |

这里的“严格”有三种不同含义：结构和容量合法；排除不可能改进的候选而不损失该搜索域的最好结果；每次接受都改善正式目标。它们不意味着每个候选、每个参数值或每个小图都一定严格提速。

尤其不移植两个不成立的推论：第一，不因第二问某个 $\beta$ 增大后变差，就断言第三问更大的 $\beta$ 都无效；第二，不把第二问“已放置块集合决定内存计数”的性质推广为“该集合决定 L2 状态和总时间”。

# 统一的执行模型

## 由方案得到执行图

对方案 $P$ 执行共享的场景 B 处理，得到
\[
 \mathcal E(P)=\bigl(\widetilde V, E_d\cup E_m\cup E_p\cup E_x\bigr).
\]
$\widetilde V$ 包含原计算操作及官方生成的搬运、换入换出操作；$E_d$ 是数据依赖，$E_m$ 是 Step3 的容量复用依赖，$E_p$ 连接同核同 Pipe 的相邻操作，$E_x$ 是跨核 COPY_OUT 到 COPY_IN 的关系。

令 $a_q,f_q$ 为操作 $q$ 的开始和结束时刻，则
\[
 a_v\ge f_u\quad((u,v)\in E_d\cup E_m\cup E_p),
\]
\[
 a_v\ge f_u+500\quad((u,v)\in E_x).
\]
必须检查子图依赖图和最终执行图，不能只检查原始计算 DAG。合并子图或固定 Pipe 顺序，都可能增加新的等待环。

**命题 1：场景 B 合法性可以继承。** 对固定原图、方案、L1/UB 和 DDR 参数，Q2 与 Q3 的场景 B 展开、Step2/Step3、固定 Pipe 顺序及跨核完成关系相同。因此 Q2 已通过执行检查的方案，在 Q3 下仍满足同样的结构与容量条件。L2 改变的是搬运时长和带宽竞争，而不是删除这些约束。

证明要点是两者共同的预处理及内存复用关系。全局执行服从同一依赖图，有限带宽和有限同步延迟不会把一个无环完成依赖图变成等待环。程序自身的迭代上限、超时或资源耗尽应另作运行状态处理，不能据此宣布图在数学上不可执行。

## 基础搬运的精确计数

在常规的单计算生产者模型中，令 $K_t$ 为张量 $t$ 的计算消费者所在核心集合；若有计算生产者，其核心记为 $k_t$。原图输入集合为 $I$，中间计算张量集合为 $J$，必须最终写回的输出集合为 $O$。则
\[
 D_{\rm base}(P)
 =\sum_{t\in I}s_t|K_t|
 +2\sum_{t\in J}s_t|K_t\setminus\{k_t\}|
 +\sum_{t\in O}s_t.
\]
中间张量也可能属于 $O$，此时跨核中转和最终写回两项均保留，符合官方逐源核—目标核插入 COPY 对的规则。直接操作边、多生产者及非常规搬运不套用这个简式，而由共享场景 B 展开器精确统计。

$D_{\rm base}$ 不是 Q3 的实际 DDR 流量，也不包含换入换出。它适合解释“分核改变了多少基础搬运”，不直接决定最终时间。

## 私有缓存占用

在某核固定的 Step1 操作序列中，令 $f_t,l_t$ 分别为张量首次、末次触及位置。COPY_OUT 也触及其输入。定义
\[
 M_{k,p}(i)=\sum_{t:\,\operatorname{pos}(t)=p}s_t\,
              \mathbf1\{f_t\le i\le l_t\},\qquad p\in\{L1,UB\}.
\]
闭区间包括当前操作的输入尚未释放、输出已经申请的瞬态。

**命题 2：固定序列的无换出充分条件。** 若整核所有位置均满足 $M_{k,p}(i)\le C_p$，则该序列不触发 Step2 的容量换出。证明是按序列归纳：每步先申请首次触及的数据，再检查容量，最后释放末次触及的数据；假设恰好覆盖这个申请前后的峰值。

这只证明没有换出，不证明该序列的 Makespan 最小。也不允许用这个静态序列的峰值代替所有核心真实并行时间线。

## 两个独立带宽池

对普通计算操作 $q$，令
\[
 d_q=\max\{1,\operatorname{cycles}(q)\}.
\]
对搬运操作，令 $b_q$ 为官方时长函数使用的搬运字节数，并定义独占参考工作量
\[
 d_q^D=\max\left\{1,\left\lceil\frac{b_q}{60}\right\rceil\right\},\qquad
 d_q^L=\max\left\{1,\left\lceil\frac{b_q}{250}\right\rceil\right\}.
\]
命中读取进入 L2 池，其余需要 DDR 的搬运进入 DDR 池。若池 $p$ 当前有 $n_p$ 个仍有工作量的在途操作，则在集合不变的区间内，每个操作的剩余独占工作量满足
\[
 w_q(\tau+\Delta)=w_q(\tau)-\Delta/n_p.
\]
一个池空闲不意味着另一个池获得更多带宽。区间内较小工作量先完成，其释放出的份额应立即重新分配；最终事件时刻按官方规则向上取整到整数周期。

## 共享 FIFO 状态

共享状态为有序队列
\[
 Q(\tau)=(t_1,t_2,\ldots,t_r),\qquad \sum_{j=1}^r s_{t_j}\le C_L.
\]
操作发射时记录其命中与否，此后不因在途 Cache 变化把这次访问的路径改掉。COPY_IN 完成时：若键已驻留，不改变顺序；若键不在且大小不超过容量，从最早项开始淘汰直至能插入，再追加到尾部。要记录每条在途读取，不能把“Cache 集合”作为全部状态。

**命题 3：FIFO 存活由插入量而非最近访问决定。** 张量 $t$ 在某次进入 L2 后，在下一次重新插入它之前，设之后成功插入的字节总量为 $A_t$。则这次驻留尚未被淘汰当且仅当
\[
 s_t+A_t\le C_L.
\]
这里不计未真正发生的重复插入，不计因超大而被跳过的插入。证明：$t$ 之前的项先被淘汰；只要 $t$ 未被淘汰，比它更新的插入项不能先被 FIFO 淘汰。故保留 $t$ 与其后全部插入项所需容量恰为左式。一旦超过容量，淘汰过程必然经过 $t$。重新插入后重新开始计算。

这条结论可解释窗口局部性，但不把原时间线上的 $A_t$ 当作修改方案后仍然不变的数值。

## 事件循环的确定顺序

初始所有核心时刻为零，L2 为空。每轮依次：结算带宽工作量；完成到期操作、处理读取完成后的 FIFO 插入并释放依赖；处理已到期的跨核释放；按官方核心和 Pipe 顺序发射可执行操作；取下一完成或跨核释放时刻继续。相同时间事件的处理顺序也应保留。

完整状态至少包括：操作完成状态及前驱计数、各 Pipe 的队首和运行项、跨核释放时刻、两池剩余工作量和上次结算时间、有序 L2 驻留队列，以及在途 COPY_IN 的查询键和访问路径。将这些量压缩成“已放置块集合”会丢失必要信息。

# 严格筛选：减少评价而不误删改进

本节下界针对**当前候选 $P$**，不是原图所有划分方案的共同最优值。当前方案达到自己的下界，不表示改变划分后不能再变快。

## 执行路径和 Pipe 下界

对潜在 Cache 读取取 $\underline d_q=\min(d_q^D,d_q^L)$，其他操作取不能缩短的时长。对不能确认缓存条件的操作，宁可使用更乐观的时长，也不强行认定未命中。

在 $\mathcal E(P)$ 中，令跨核关系的边延迟为 500，其余为零，计算
\[
 L_{\rm path}(P)=\max_{q_1\to\cdots\to q_r}
 \left(\sum_{i=1}^r\underline d_{q_i}+\sum_{i=1}^{r-1}\ell_{q_iq_{i+1}}\right),
\]
\[
 L_{\rm pipe}(P)=\max_{k,p}\sum_{q:\,k(q)=k,\,p(q)=p}\underline d_q.
\]
每条依赖路径必须完成其全部操作，同 Pipe 必须串行，因此两者均不超过真实 Makespan。

## 兼顾两个带宽池的下界

对执行展开后具有相同逻辑键、相同正大小、相同独占搬运工作量的 COPY_IN 分组。组 $t$ 有 $m_t$ 次读取，独占工作量为 $d_t^D,d_t^L$。空 Cache 开始至少有一次未命中，故命中次数 $h_t$ 满足 $0\le h_t\le m_t-1$。

设 $W_D^0$ 是不能由 L2 服务的确定 DDR 工作量。忽略读取释放时刻、FIFO 淘汰和先后约束，并允许 $h_t$ 为实数，得到
\[
 \begin{aligned}
 L_{\rm bw}(P)=\min_{\lambda,h}\quad &\lambda\\
 \text{s.t.}\quad&W_D^0+\sum_t(m_t-h_t)d_t^D\le\lambda,\\
 &\sum_t h_t d_t^L\le\lambda,\\
 &0\le h_t\le m_t-1.
 \end{aligned}
\]
超过容量且逻辑大小一致的组强制 $h_t=0$。不满足上述分组条件的非常规读取，采用更弱的放松或从该带宽下界中略去其贡献，仍用官方程序评价；不强行套用“首读一次”的公式。

**命题 4：$L_{\rm bw}(P)\le T_3(P)$。** 把真实执行中的整数命中次数代入约束，两个池各自完成的总独占工作量均不超过全程时间。上述模型还去掉了一部分约束并放松整数性，其最优值不会更大。

该小型模型不必调用大型优化软件。给定候选时间 $x$，在 L2 工作量预算 $x$ 内，优先给 $d_t^D/d_t^L$ 较大的组增加 $h_t$，直到预算或上限用完，即得到能够最大减少的 DDR 工作量。它是连续分配问题；按比值排序后分段求交即可。原型使用有理数精确计算交点，未用近似小数向上取整来冒充严格排除条件。

综合下界为
\[
 L(P)=\left\lceil\max\{L_{\rm path}(P),L_{\rm pipe}(P),L_{\rm bw}(P)\}\right\rceil.
\]
当前最好目标为 $(T^*,D^*)$，而候选的官方额外搬运量在预处理后已知。只有
\[
 L(P)>T^*,\quad\text{或}\quad L(P)=T^*\ \text{且}\ D_{\rm add}(P)\ge D^*
\]
时，才可跳过完整全局模拟。$L(P)=T^*$ 但搬运量更小时仍应评价。

**命题 5：上述筛选不删除能严格改善当前字典序目标的候选。** 第一种情况时间不可能达标；第二种情况即使达到下界，次要指标也不能改善。其他情形没有被排除。

这项筛选发生在执行图准备之后，主要节约全局事件模拟；不能把节约的调用数解释成已经省掉全部 Step1—3。对同一候选序列，本次关开该筛选得到完全一致的最终方案，调用数对照见实验部分。

# 容量窗口处理：保留第二问的精确部分

仅在当前官方结果存在实际换入换出时，启动专门的容量修复。没有实际换出的核心不运行这类 DP，但仍可进行与时间有关的调序或迁核。

固定分核、块内顺序、窗口外顺序，选择同核连续 $w\le8$ 个计算块。保留原计算依赖中穿过窗口外的路径，以及窗口两侧的必要顺序；不能只检查块之间的直接边。多生产者等超出该 DP 简化条件的局部结构，跳过 DP，仍允许走普通候选和官方评价。

令块集合为 $W=\{0,\ldots,w-1\}$，$X\subseteq W$ 表示已放置集合。COPY_IN 应归入新顺序中最早使用其输出的子图，不能保留原归属不动，也不能一律堆到块头。桶内仍按真实 Step1 原相对次序排列。

对相关张量 $t$，设 $a_{tj}$ 是块 $j$ 固定事件的触及次数，$c_t^0$ 是窗口前次数，$C_q$ 是一个可移动 COPY_IN 在窗口内的消费者块集合。则边界计数可写成
\[
 c_t(X)=c_t^0+\sum_{j\in X}a_{tj}
       +\sum_{q\in\mathcal I}a_{tq}\,\mathbf1\{C_q\cap X\ne\varnothing\}.
\]
$\mathcal I$ 只包含此前没有在窗口外先消费、确实随窗口首次消费移动的输入。若窗口前已有消费者，该 COPY_IN 留在窗口前，不再次计入。

给定 $X$ 和下一个块 $j$，按新桶顺序扫描其完整事件：首次触及先申请空间；同时检查 L1 和 UB；触及计数增加后，若已到全核末次触及才释放。这样包括输入输出同时存在的时刻。窗口之外但持续驻留的字节作为固定项加入。

令 $d[X]$ 为到达 $X$ 的最少逆序对数，初始 $d[\varnothing]=0$。当 $j$ 的必要前驱已放置、上述逐事件占用不超容量时，
\[
 d[X\cup\{j\}]=\min\left\{d[X\cup\{j\}],\
 d[X]+|\{i<j:i\notin X\}|\right\}.
\]
同值取块编号序列字典序较小者。

**命题 6：该 DP 在所规定的固定窗口域内求得容量可行、逆序对数最少的排列。** 每个集合 $X$ 唯一决定已发生的固定事件集合、已触发的输入搬运集合及触及计数；所以后续容量可行性与费用只需 $X$。逆序对增量正是新块跨过尚未放置的旧前方块数量。由子集归纳得到结论。

该证明**不能**替换为 L2 时间最优的证明。两种达到同一 $X$ 的顺序，可能有不同 FIFO 顺序、正在运行的读取、剩余带宽工作量和各 Pipe 时钟。Q3 的时间选择仍需完整事件评价。

应用候选后必须重建实际 Step1，核对预期完整含 COPY 的序列，重新检查整核占用和执行合法性。该 DP 的最优性仅针对所定义的容量与顺序条件；若最小扰动解没有通过后续全局执行检查，只能拒绝此候选，不能由此断言其他容量可行排列也都不可执行。窗口内无可行排列只表示本窗口受限域未解决，不表示原图非法。时间到期是“未完成”，不是“所有排列不可行”。

本次原型实现并验证了“整核子图数不超过 8”的固定域版本；正式滑动窗口版本按上述前缀与外部驻留处理接入已有 Q2 窗口组件，不把它列为本轮已经完成的百例代码验收。

# 第三问新增的候选与诊断

## 从实际读取而不是单纯顶点度数开始

重新评价当前方案后，对每个逻辑键统计：实际 COPY_IN 次数 $m_t$、未命中次数、重复未命中字节、首读完成时刻、各次读取时刻、FIFO 插入与淘汰，以及读取对应的计算块。

静态潜在复用量
\[
 U_t=(m_t-1)_+s_t
\]
是读取次数固定时的理想重复字节量，不是实际节省。可用
\[
 V_t=(m_t^{\rm miss}-1)_+\,(d_t^D-d_t^L)
\]
排列值得检查的键。它只产生候选，不作为接受条件；不将首读必然未命中当作算法错误。

另从当前完整时间线构造两类诊断：实际换入换出；关键或接近关键的计算块。后者可在冻结当前操作持续时间和执行关系后计算后续最长路，作为候选优先级。修改方案后这些持续时间可能变化，所以它不是安全排除条件。

## 读取顺序调整

针对有重复未命中的键，尝试把对应消费块在同核局部向前或向后移动，或交换相邻块。默认只检查邻近距离 $1,2,4$，窗口不超过 8 块，每轮优先处理至多 8 个高价值键。

向前移动希望在淘汰前使用；向后移动希望避开尚未完成的首读。这两种方向都要允许，不能统一强迫延后或统一强迫提前。每个候选均重建实际搬运，再评价全局时间。

**条件性收益说明。** 在只有 $r$ 个相同数据读取、没有其他竞争且合法调序确实能够实现先后关系的受限情形，全部同时未命中需要 $r d^D$；一次 DDR 首读完成后，其他 $r-1$ 次由 L2 服务需要 $d^D+(r-1)d^L$，差为
\[
 (r-1)(d^D-d^L)>0.
\]
这解释了候选的来源，但并不保证一般图上故意延后读取有益。一般图还包含计算关键路径、输出写回和空间复用等待，必须正式评价。

## 迁核、局部拆分和整分量处理

保留第二问的整计算分量同核候选。其严格优点是没有分量内部的计算中间张量跨核中转；缺点是不同分量仍可能通过输入和带宽互相影响，不能分别算好后简单相加。

对当前较晚结束的核心，选择至多 8 个块，考虑完整迁移到较轻核心，或迁到共享输入更多的核心。目标核心采用“较轻负载”和“较强数据共享”两类来源的并集，每块最多 3 个目标核；使用保持依赖的前端、后端及邻近消费块位置。不能仅保留若干空闲核心而永远不考虑有数据局部性的已用核心。

对较大子图，沿其实际计算拓扑序选取约 $1/4,1/2,3/4$ 的切点，构造拆分后迁移一部分的完整候选，不拆分单个操作。

沿已有子图内部拓扑序切成连续区间不会使原有子图依赖图产生环：若新环经过不同旧子图，收缩后违反旧图无环性；若新环全部在同一旧子图内，则违反区间先后方向。不过这不代替新的 Pipe、内存复用及跨核关系检查。

相反，同核合并子图在场景 B 下并不自动节省边界搬运，因为同核原本已是一个 Task。合并可能改变排序，也可能让经外部子图返回的依赖形成环；不照搬问题一“合并就省一次 Task 等待”的成本公式。

## 停滞后的局部联合调整

仅允许“每个单独动作都先变好再继续”会遗漏组合改善。故当单独重排、迁核、拆分均未改进时，增加一个受限域：**一次迁核加原核附近至多 4 块的重排，作为一个完整方案评价。** 也可交换两个核心的块而不要求先完成一边的单独迁移。

候选排序采用少量明确方向：原顺序、末块前移、首块后移、反向优先的合法拓扑序。生产实现先做依赖筛选，再保留至多 24 个联合候选；不枚举全图所有排列，也不依赖先接受一个坏方案。

本次确实遇到并修复了这种停滞：一个共享输入对照图的最好 Q2 参照为 8103 cycles；只重排和单独迁核都停滞；加入完整的迁核—调序候选后降到 7481 cycles。

# 核数适应与总预算

## 保留“更多可用核不会强迫使用更多核”

**命题 7：尾部增加空核心保持执行时间。** 将 $N$ 核方案原样保留，在 `core_schedules` 尾部补空列表成为 $N+1$ 核方案，不改变已有操作归属、原核心编号、子图顺序或映射次序。场景 B 展开及已有核心事件顺序保持一致，新增空核没有操作，因此 Makespan、搬运量、Cache 访问及命中统计不变。

由事件归纳即可证明：初态一致；已有事件及带宽参与集合一致；新增空核没有可发射操作；故下一事件也一致。

所以第三问按核数递增求解时，将同一轮已得到的较少核数方案补空核后作为额外初值，并重新核验。于是
\[
 T_3(P^*_{N+1})\le T_3(P^*_N).
\]
这个保证针对本算法保留的方案，不是要求负载必须铺满所有核心。它不保证“相对各自无 L2 基线的加速比”随核数也单调，因为分母不同。

本次独立搜索出现 2 核 10722、4 核 10962、5 核 12003 的选择退化；补入上述初值后，2—5 核均保留 10722。禁止空闲核心反而会删除这些可行方案。

## 可解释的图特征与粒度

继承第二问的计算负载 $W_M,W_V$、后续路径量 $b(v)$、计算弱连通分量、私有内存压力。新增实际重复读取量及 FIFO 淘汰量。原始度分布可辅助分类，但不能替代实际 COPY_IN 的复用统计。

保留粒度参考式
\[
 L_\beta=\max\left\{1,\left\lceil\frac{\max(W_M,W_V)}{\beta N}\right\rceil\right\},
 \qquad \beta\in\{1,2,3,4\}.
\]
它用于大块拆分或局部构造的计算规模参考，不把它当作硬件时间。已有 Q2 最终方案时，默认不重新跑完整 Q2 的全部参数流。若局部重构确需参数反馈，必须使用本轮 Q3 成绩；参数增大后的成绩不假定单调。

## 单个原图的共享预算

正式设计按一个原图所有请求核数合计约 600 秒安排，目标环境为单 CPU 计算流程；个别图可单独记录延长。预算从读取输入、重建初值开始，包含准备、搜索、结果写出和最终重新评估。这是比“每核数各跑十分钟”更保守的项目计算约定。

先为各核数建立合法初值，再按核数轮转分配小批候选；出现改善后更新诊断并回到较便宜的处理层。最终重新评估预留取最近实际耗时的保守估计，例如各核数预计评估时间总和的 1.5 倍，再加输出时间。若剩余时间不足以启动并完成一批工作及最终检查，就停止生成新候选。

建议起始上限为：每类最多 8 个诊断种子；容量窗口最多 8 块、每轮最多 8 个窗口；单项重排每种距离双向考虑；迁核目标最多 3 核；停滞联合域至多 4 块、24 个完整候选。大图根据已测单次准备时间减少候选数，不能依赖固定调用数保证十分钟。

窗口宽度可按已测事件处理成本选择。令 $a$ 为单位转移事件扫描的保守秒数估计，$e_w$ 为窗口相关事件数，$b$ 为本窗口剩余预算，则从 $\{4,6,8\}$ 中选最大满足
\[
 a\,e_w\,w2^w\le b
\]
的宽度；不足则记录未搜索，而非不可行。整个检查仍需可终止的预算控制，不能只相信一次估计。

正式进程应给完整官方评价设置可终止的子进程时限，超时回收后保留最近已验证方案；最终未通过复核时不能发布“成功”。附带小图原型采用两次评价之间的时间检查，没有宣称提供了大图硬超时保证。

# 完整算法流程与模块接口

## 主流程

```text
输入：原图、固定配置、各核数的 Q2 最终方案、全图时间预算
输出：各核数的 Q3 最终两字段方案及独立统计文件

1. 读取原图并建立共享依赖、张量和计算分量索引。
2. 对每个核数，从最终方案重建当前结构；执行 Q3 正式评价。
   保存各核数最好的已验证初值；不使用旧 Q2 中间状态。
3. 按核数递增，把较少核数的最好方案补空核加入较大核数初值。
4. 在剩余预算内轮转各核数：
   a. 从当前 Q3 时间线诊断重复未命中、淘汰、私有换出和晚完成块。
   b. 有实际换出时生成容量最小扰动候选；同时生成少量局部调序候选。
   c. 没有改善时生成迁核、交换和局部拆分候选。
   d. 仍停滞时生成小范围迁核—调序联合候选。
   e. 对每个候选：
      检查覆盖与子图依赖；重建实际场景 B 状态及必要准备；
      检查最终执行关系；计算严格下界；
      不能排除时做 Q3 双带宽事件评价；
      仅当 (Makespan, 官方额外搬运量) 严格改善时替换当前最好方案。
   f. 有改善则更新诊断并返回便宜层；本轮无改善则暂停该核数。
5. 保存结果前，用原版官方入口对当前最终文件独立重新评估。
6. 输出相同核数下无 L2 / 有 L2 的逐用例指标及对比曲线所需数据。
```

不需要把一个没有验证的近似方案覆盖掉最好方案。当前最适合先使用严格下界和共享准备后的精确全局评价，而不是先假定必须引入一个不可靠的 Cache 命中概率模型。未来如增设近似模型，只用于候选排序或有限探索；正式保留方案仍以已确认的 Q3 分数为准。

## 模块划分

| 模块 | 输入与输出 | 与 Q2 的关系 |
|:--|:--|:--|
| 方案导入 | 原图、最终两字段 JSON → 当前状态 | 使用 `build_state/derive_state` |
| 场景 B 准备 | 当前状态 → 本核图、Step1、Step2/3、跨核关系 | 共享 `PreparationService` 及官方处理 |
| L2 事件模型 | 已准备执行图 → Q3 时间线、命中及路径 | 新增 Q3 专用全局模型 |
| 诊断 | 当前 Q3 结果 → 读取、容量、关键块信息 | 保留私有容量，新增 L2 时序 |
| 候选生成 | 当前块、诊断、预算 → 完整合法表示的提案 | 共享容量窗口；新增联合调整 |
| 严格筛选 | 候选执行图、当前目标 → 保留或排除 | 新增双带宽下界 |
| 正式择优 | Q3 正式分数 → 最好方案 | 沿用字典序及已验证结果保留 |
| 核数协同与输出 | 各核数方案 → 补空核初值及最终报告 | 新增共享预算与核数保底 |

## 接口接入的四个注意点

第一，Q2 的状态构造接口负责结构；不能直接更改它的环境字段，再把这个修改后的对象交回原 Q2 校验器，否则会被重新构建检查判为不一致。建议保留一个原 Q2 结构对象，再建立包含 Q3 配置的评分对象。附带 `q2_adapter.py` 按此方式组合现有类，原结构只交给 Q2 的检查和派生函数。

第二，Q3 的评价标识必须包含问题编号、输入与计划、L1/UB、DDR、跨核延迟、L2 容量、L2 带宽、FIFO 实现及官方版本。相同 JSON 在 Q2 和 Q3 下不能共用最终分数。第二问关于“同一执行”的判断可用于结构复用，但 Q3 的最终数值还需要自己的配置条件。

第三，保留 JSON 映射插入次序和官方敏感的列表次序。只改子图编号也未必是无影响的更名；必须实际确认展开图与序列。不同核心的物理张量不能在私有容量计算中合并；逻辑张量标识只用于共享 L2 数据识别。

第四，局部迁核不表示只重算这两个核心的全局时间。它可能改变源核 COPY、合成编号、其他核的读取时刻、DDR 竞争和 FIFO 顺序。准备结果只有在完整输入条件一致时复用；全局事件时间应重新计算。计算结果复用表与硬件 FIFO 是两个不同对象，不把软件复用表的替换方式当作 L2 的规则。

## 复杂度与可实现性

设展开后操作数为 $n'$，执行关系数为 $m'$。已有 Step1—3 的成本单独记为 $C_{\rm prep}$，不未经证明称其整体线性。紧凑的全局事件实现每次最多处理 $4N$ 个运行操作、至多 $2N$ 个带宽搬运；加上依赖更新和事件管理，可按
\[
 O\bigl(m'+n' N\log(N+1)+n'\log(n'+1)\bigr)
\]
安排其数据结构。$N\le5$ 时全局部分有较小的资源状态。

窗口 DP 至多 $2^w$ 个集合和 $w2^{w-1}$ 次集合转移，但每次转移还要扫描有关事件，不能称为常数时间。候选总成本由实际准备次数、全局模拟次数和窗口事件扫描次数决定，不只由“候选不超过几个”决定。

保留有限大小的本核准备结果和正式分数摘要；被拒绝候选通常不长期保存完整大时间线。实际内存应测进程占用，不能把复用表的序列化字节上限写成整个进程内存上限。

# 小案例试跑、失败诊断与修复

## 试验条件与参照

使用上述固定配置。核对后的官方 Q2/Q3 评估文件、Step1—3、合法性检查及方案检查文件与仓库 Git 对象校验值一致。运行使用其实际函数。用于导入的 Q1 辅助模块只保留两段实际被使用的统计函数；无关命令行模块用错误输出辅助函数代替，未改变数值评价逻辑。最终重新评估重新调用原官方数值函数并比较完整结果 JSON；本轮没有将这个同进程、重新构建的函数调用描述为已运行完整官方命令行子进程。完整范围和文件校验值见代码包清单。

环境为 Linux、Python 3.13.5，串行执行。仓库目标环境是 Python 3.12；本轮没有把 3.13.5 的运行记录写成 3.12 的测试记录。小图的毫秒级时间不能外推正式图的十分钟性能。

共享输入对照图均有四个计算操作 $A,B,C,D$，输入使用关系为
\[
 A:x,\quad B:x,y,\quad C:y,z,\quad D:z.
\]
计算使用 Cube，每个结果为 16 bytes，经官方写回。三输入大小及计算周期如下。

| 图 | 输入大小 $(s_x,s_y,s_z)$，bytes | $(d_A,d_B,d_C,d_D)$，cycles |
|:--|:--|:--|
| S1 | (30000,30000,30000) | (1500,200,6000,1500) |
| S2 | (60000,30000,30000) | (400,800,6000,200) |
| S3 | (60000,120000,60000) | (200,6000,6000,100) |
| S4 | (120000,120000,60000) | (800,3000,100,1500) |

为避免只拿一个很差初值展示改进，这四个控制图的 Q2 参照是在**每个计算操作单独表示为一个子图**的域内，检查全部 120 种两核操作列表表示后取得的最好 Q2 字典序目标。这个离线小规模检查仅用于校验参照和答案，不属于在线求解算法，也不声称涵盖所有可能的子图合并表示。

## 主要结果

| 图与核数 | $T_2$ | $T_{2\to3}$ | 最终 $T_3^*$ | 额外算法加速比 |
|:--|--:|--:|--:|--:|
| S1，2 核 | 8001 | 7881 | 7121 | 1.1067 |
| S2，2 核 | 8001 | 8001 | 7121 | 1.1236 |
| S3，2 核 | 12004 | 12004 | 10722 | 1.1196 |
| S4，2 核 | 8103 | 8103 | 7481 | 1.0831 |
| 仓库交错内存小图，2 核 | 3736 | 3736 | 2302 | 1.6229 |
| FIFO 压力对照图，3 核 | 56018 | 56018 | 37014 | 1.5134 |
| 最小输入输出图，2 核 | 6 | 6 | 6 | 1.0000 |

内存小图故意使用仓库中的交错方案测试继承组件，**不是把已经修复的第二问最终方案重新说成 3736**。它的额外换入换出由 80000 bytes 降为 0，说明该处理在 Q3 仍有效，但这项改善不应全部归功于 L2。

FIFO 图使用 9 个各 180000 bytes 的输入，共 18 个独立计算操作，每个 2000 cycles，3 核给定列表。全部不同输入大小合计 1620000 bytes，确实超过固定 L2；不是通过改小 Cache 配置制造压力。最后方案命中率为 35.2941%，官方额外搬运量由 1620000 降到 1440000 bytes。该次达到候选预算后停止，不称其为全局最优。

S3 的额外搬运由 120000 增到 180000 bytes，时间仍显著改善。S4 的额外搬运由 0 增到 240000 bytes，时间由 8103 降到 7481。它们说明不能把“额外搬运不得增加”设为第一层硬限制。

## 性能下降：命中率目标不可靠

S1 的初始 L2 结果是 7881 cycles、命中率 20%。另一个合法方案命中率提高到 40%，却用了 10502 cycles，慢约 33.3%。修正后的选择规则拒绝该方案；最终找到同为 40% 命中率但只需 7121 cycles 的方案。

S2 的初始和最终命中率都为 $1/3$，时间却由 8001 降到 7121。这进一步表明：不仅命中多少重要，哪一条关键读取命中、何时完成以及是否阻塞后续计算更重要。

单核换入对照也有相反现象：无 L2 为 4202 cycles；保持原计划启用 L2 后为 3102、命中率 $1/3$；容量调序消除 60000 bytes 的换入后，时间仍为 3102，但命中率降到 0。消除一次不必要读取不应因为“命中率下降”被拒绝。

## 停滞修复一：迁核与局部顺序一起改变

第一版仅有单独重排、迁核和交换时，S4 仍停在 8103。检查完整结果后发现，迁核同时改变原核剩余输入的首次读取顺序才有收益；单独变化并不足够。

增加受限的迁核—调序完整候选后，S4 降到 7481。为避免只修一个图，重新检验 40 张固定随机种子的四操作同族图。修复前 7 张严格改善、36 张达到该表示域中的已枚举最好时间；修复后 11 张严格改善、29 张时间持平、0 张退化，40 张均达到该表示域中的最好时间。平均额外算法加速比由约 1.0140 变为 1.0177。

这不是百例泛化保证，而是一个明确的“观察停滞—检查完整方案—修改候选域—重新覆盖全部小样本”的修复过程。

## 停滞修复二：较少核数方案补空核

以 S3 的整分量负载初值作 1—5 核对照，独立搜索曾得到以下时间：1 核 15102，2 核 10722，3 核 10722，4 核 10962，5 核 12003。检查后确认这不是更多核导致物理可行域变小，而是有限候选选择没有保留较少核数的好方案。

加入命题 7 的初值后：

| 可用核数 | 无 L2 参照 | 原计划启用 L2 | 修复后的最终时间 |
|--:|--:|--:|--:|
| 1 | 15301 | 15301 | 15102 |
| 2 | 12201 | 12201 | 10722 |
| 3 | 14004 | 13003 | 10722 |
| 4 | 14004 | 13003 | 10722 |
| 5 | 14004 | 13003 | 10722 |

该表是控制图的机制检验，不是正式题目的一核基准曲线。

## 其他核验

在 20 张含计算依赖、两种计算 Pipe 和共享输入的小图上，12 张时间改善、8 张持平；25 个非法候选被拒绝，没有以跳过依赖的方式取得成绩。这组试验以全部计算放入核心 0 的单子图方案为初值，主要验证依赖处理和候选合法性，不把这组改善比例当作对第二问新基座最终方案的性能提升比例。

对 44 个最终方案，从完整全局时间线和实际物理张量生产—消费关系重新计算 L1/UB 占用，全部不超过固定容量。这项检查没有仅重复读取官方核内峰值字段。

对带宽放松做了 200 组小规模整数命中分配对照，放松下界均不超过整数参考最优值。容量 DP 在仓库内存小图上得到最少 1 个逆序对的无换出排列，并与该受限域的完整小规模对照一致。

关闭与开启严格筛选，在四个共享输入图上得到完全相同的最终计划和完整结果；搜索中的全局评价调用数如下，另各有一次独立最终重新评估：

| 图 | 无严格筛选 | 有严格筛选 | 结果是否相同 |
|:--|--:|--:|:--|
| S1 | 30 | 10 | 相同 |
| S2 | 30 | 18 | 相同 |
| S3 | 33 | 18 | 相同 |
| S4 | 42 | 42 | 相同 |

这证明本次实现对这些固定候选序列没有以牺牲结果换取调用减少；没有把调用减少比例宣称为整套算法的同等耗时降幅。

# 收敛、改进保证与正式验收

**命题 8：正式输出不劣于 Q3 初值。** 当前方案只在字典序目标严格改善时更新，且初值和最后方案均经 Q3 正式评价。因此
\[
 F(P^*)\le_{\rm lex}F(P^0),\qquad T_3(P^*)\le T_3(P^0).
\]
若所实际评价的候选中存在严格更好的目标，算法就会保留一个严格改进；若某候选被严格下界排除，它本来也不能改善当时的最好目标。有限候选和有限预算使流程终止。

不能进一步宣称每张图都必然严格提速。最小图的一次 16-byte 读、4-cycle 加法和一次 16-byte 写构成至少 6 cycles 的必要依赖链；官方时间已为 6，本次保持 6 正是正确行为。对原本接近最好状态、没有可复用输入或被长依赖链限制的图，也应允许停止并保留原方案。

正式提交前应在全部原始用例和固定配置上完成：每个请求核数的合法最终 JSON；Q2 固定无 L2 参照与 Q3 结果；官方 Makespan、额外搬运和字节命中率；原计划直接启用 L2 的中间对照；整个原图的串行用时、未完成的搜索域及最终独立重新评估结果。结果未齐全时，不把部分均值标成百例平均值。

本设计的优先实现顺序是：共享 Q2 准备与最终方案导入，Q3 精确事件评价与口径核对，读取调序和原容量 DP，迁核—局部重排联合候选，核数补空核保底，最后再对大图准备开销和候选预算调优。不以额外增加大量自由权重代替对执行机制的核对。
