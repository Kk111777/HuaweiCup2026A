# Q2 自适应 β：与 Q1 的衔接、消融及验证

版本：`Q2-Baseline-AdaptiveBeta-1.1`。默认配置位于 [`configs/q2/baseline.json`](../../configs/q2/baseline.json)，入口为 `src/solve_problem2.py`，Python 3.12、标准库。

## 1. 为什么改变初始化

1.0 按交接稿完整构造至多八个候选，以代理量排序，取首个官方有效方案。它没有包含 Q1 已实现的自适应 β 组件。用户明确要求沿用这一组件后，1.1 将初始化改为逐候选取得完整 Scene B 官方反馈、各模式独立早停、保留已评价的最好方案。

来源是 [`q1/solver.py`](../../src/q1/solver.py) 的 `initialize(beta_search=...)` 及 [Q1 初始化说明](../q1/initialization.md)。Q2 只移植参数搜索规则，使用自身的构造器、Scene B 官方评价和预算管理；不调用 Q1 的核心分配或 Task 等待模型，也不修改 Q1 源码与历史结果。原交接[设计](design.md)和[验收合同](acceptance_contract.md)保持原样，其中关于廉价排序、仅评价首个有效候选及调用次数的条款属于 1.0。

用户提供的 Q1 五核消融表中，Full / w/o Adaptive β 的平均加速比分别为 3.3388 / 3.2775，平均求解时间为 119.28 / 63.65 秒。这张表支持该组实验中的性能收益，不支持“相对 fixed 同时减少墙钟时间”。Q1 当前 `fixed` 的定义是两个模式只试 β=1；相对 `grid` 的早停可以减少候选构造，但实际墙钟收益仍需在相同环境下测量，不能从候选数直接推出。

## 2. 搜索规则

默认候选 β 为 `[1, 2, 3, 4]`；可以配置为从 1 开始的连续前缀，禁止跳跃、乱序、重复。每个 β 的子图生长阈值仍为

\[
L_\beta=\max\!\left(1,\left\lceil\frac{\max(W_M,W_V)}{\beta N}\right\rceil\right),
\]

其中 (N) 为模拟核心数，(W_M,W_V) 为整图两类计算操作的工作量总和，单操作工作量为 `max(1, cycles)`。种子超出阈值时保留原有种子保护规则。四类短名单、核心试放、生长接受条件与增量状态均保持原实现。

令 (m) 为 `global` 或 `component_grouped`，(T_{m,b}) 为 β=b 构造方案的官方 makespan，(D_{m,b}) 为官方 added COPY bytes。

| `--beta-search` | 候选访问规则 | B0 选择 |
|---|---|---|
| `adaptive`（默认） | 每模式从 β=1 开始；成功后试 β=2；此后仅当 (T_{m,b}<T_{m,b-1}) 才继续下一 β | 所有已成功评价候选中官方字典序最优 |
| `fixed` | 每模式只试 β=1，作为关闭组件的消融 | 同上 |
| `grid` | 每模式尝试配置中的全部 β，包括前一候选失败后的其他 β | 同上 |

自适应在周期持平、变差或候选失败时停止该模式；另一模式独立继续。到达最大 β 后结束。时间持平但搬运减少的候选仍可以更新 B0，但不触发继续搜索。`proxy_J` 和无换出峰值仍作为构造/诊断量，不代替官方反馈。三个策略共用最终候选排序键

\[
(T_{m,b},D_{m,b},\operatorname{order}(m),b),
\]

其中 `global` 的模式序号为 0，`component_grouped` 为 1。输入图只有一个弱连通分量时按原实现省略重复的 grouped 搜索。无成功候选时，才尝试并官方验证单操作后备方案。

每次构造都新建状态；在同一构造内关闭子图、切换 scope 时保持核心时钟、驻留及搬运状态。Q2 串行轮转活跃模式，先尝试各模式 β=1，再逐轮递增。Q1 当前串行实现按模式连续推进；在候选评价均完成且无墙钟截断时，两者各模式的访问集合、停止规则和 B0 择优一致。Q2 的轮转用于优先覆盖各模式的 β=1，预算不足时仍可能无法完成全部基线候选。

## 3. 评价复用与预算

- 相同输入、官方版本和本次求解环境下，完全相同 `plan.json` 的成功官方评价可以复用。缓存保存官方目标、前缀证书摘要、来源候选/调用索引和结果路径，不同时保留八份完整官方结果。完全相同方案再次出现时跳过重复前缀、证书和官方子进程，但该 β 的构造成本仍已发生。
- 仅执行图签名相同而方案不同，不复用完整官方结果；子图边界和结果元数据可能不同。失败、超时和未完成评价不缓存。缓存不会跨 case、核数、策略运行或进程复用。
- 命中缓存得到相同官方周期时，自适应按“持平”停止；这不是跳过 β 的额外探测。最终落盘方案始终独立启动官方 CLI 全字段复评，不能用缓存代替。
- 默认总预算 600 秒、初始复评预留 60 秒，仍支持命令行覆盖。构造检查保留初始评价与最终复评余量；每次实际官方评价后更新耗时估计与预留。初始化已取得 B0 后，如果后续构造因预算中断，保留 B0 进入原有增强/最终复评流程。同步构造检查为协作式，不承诺全调用硬截止。

在所有 β=1 基线候选成功完成、评价一致的前提下，自适应的 **B0** 不劣于 fixed 的 B0。该结论不适用于固定总预算下未访问的候选，也不保证两次运行各自窗口增强后的最终方案有同样的支配关系。严格早停不假设 β 与周期单调，可能错过“先持平或变差、后改善”的更大 β；保留 grid 正是为检查这种情况。

旧版 case_086/N5 的 β=1、2 方案哈希完全相同，而旧版廉价排序最终选中 β=3。1.1 自适应会因前两者持平而在 β=2 停止；不能宣称它必然优于 1.0 或完整网格。

## 4. 命令、记录与版本隔离

对同一批输入、核数、时间预算及窗口设置，只改变搜索开关；使用不同输出目录。例如在仓库根目录运行以下有限对照：

```powershell
foreach ($policy in @('fixed', 'adaptive', 'grid')) {
    python -X utf8 src/solve_problem2.py solve official/data/case_001.json --cores 2 --beta-search $policy --wall-seconds 90 --verification-reserve 15 --output-dir "outputs/q2_beta_compare/$policy"
}
```

`solve`、`batch` 均支持该开关；省略时读取配置中的 `construction.beta_search`，默认 adaptive。`fixed` 的有效 β 集合为 `[1]`，不会因配置中保留了 1–4 而运行其他值。三策略共用官方最优 B0 选择，1.1 的 grid 不是 1.0 的“廉价排序、首个有效”策略；需要旧版对照应另用合并提交 `09d4d6f` 的独立检出和输出目录。

`run.json` / `progress.json` 的 `search` 保存策略、轮转顺序、逐模式 `evaluated_betas`、最好官方目标和停止原因；每候选保存 `objective`、`evaluation_status`、`official_call_index` 和 `search_decision`。缓存命中另有 `reused_candidate_index`。`evaluated_candidates` 计入有判定的失败候选和缓存命中，与实际启动的 `official_evaluations` 分开；构造中断计数单独保留。CSV 增加策略、选中模式/β、初始化候选数、实际官方调用数和缓存命中数。

新算法版本、策略配置以及 `q2/beta.py` 等源码均进入指纹。1.0 配置会明确报错；不静默升级旧配置，不续用旧成功目录，不重标历史成绩。`--resume` 仍只复用同版本、同策略、同来源且产物校验通过的成功组合。

## 6. 两个真实组合的有限对照

另用原始 case_001/N2 与 case_086/N5 分别运行 fixed、adaptive、grid，共六次；Windows、Python 3.12.14、workers=1、每组合 90 秒预算 / 15 秒复评预留，窗口设置保持默认。三策略按 fixed → adaptive → grid 串行执行，每策略内部先 001/N2 再 086/N5。一次加载并校验固定单核归档后，通过 `solve(..., baseline=catalog[case])` 传入对应记录。全部结果均独立官方复评成功，未启动其他 case。

| case / N | 策略 | 选中 β | 完成候选数 | 初始化实际官方调用 / 缓存命中 | 最终 makespan / cycles | 求解墙钟 / s |
|---|---|---:|---:|---|---:|---:|
| 001 / 2 | fixed | 1 | 2 | 2 / 0 | 116868 | 3.546 |
| 001 / 2 | adaptive | 1 | 4 | 2 / 2 | 116868 | 5.219 |
| 001 / 2 | grid | 1 | 8 | 2 / 6 | 116868 | 5.296 |
| 086 / 5 | fixed | 1 | 1 | 1 / 0 | 114764 | 24.125 |
| 086 / 5 | adaptive | 1 | 2 | 1 / 1 | 114764 | 35.141 |
| 086 / 5 | grid | 4 | 4 | 3 / 1 | 103320 | 67.078 |

六次均选择 global 模式，最终均保留 B0。表中的“初始化调用数”不含 B1 和最终复评；完整实际官方调用数依次为 3、3、3、3、3、5。case_086/N5 的 beta=1、2 为同一方案，自适应按周期持平停止；grid 继续到 beta=4 后找到更好的官方周期。这一实测确认早停可能牺牲后续收益，不能声称移植后对所有 Q2 输入同时改善周期和求解时间。

这是各组合单次有限冒烟，不是默认 600 秒预算的正式消融，也没有随机交错重复或独占 CPU 控制；墙钟不能作为稳定提速估计。三个策略当前 B0 的选择口径均为官方最优，与 1.0 廉价排序口径不同，不能把 grid 的收益全部归因于 β 搜索开关。
