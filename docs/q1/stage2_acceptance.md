## 8. 历史审阅发现与保留边界

2026-09-25 的独立审阅基于 `86945d0` 及当时未提交的第二阶段源码，额外用 10 张固定种子小图、350 个合法完整方案对照关闭/开启剪枝后的局部最优目标，10/10 一致。该有限检查不构成全局最优证明。完整变量、公式和三层流程统一见 [stage2.md](stage2.md)，原审阅全文保留在开发者本地快照中。

| 边界 | 当前行为与使用要求 |
|---|---|
| 将第二阶段 `plan.json` 再作为独立初值 | 同目录存在 `complete.json` 且文件名为 `plan.json` 时，当前读取器按阶段一归档校验，会要求 `construction.json`。继续优化应使用 `checkpoint_plan.json` 或另存到独立目录/文件名；这会建立新起点和新预算，不是搜索栈续跑。 |
| 官方模拟失败与评价预算 | 预算沿用原实现的成功评价语义，失败调用不消耗成功评价名额。时间限制仍适用；不应把 `budget_evaluations` 解释为所有尝试调用数。本轮按保持预算逻辑的要求保留此行为。 |
| `pruned_candidates` 的统计粒度 | 总数混合部分分支和完整方案排除，不能解释为省下同样次数的官方模拟。需按 `optimization.json` 记录的 `scope` 分别统计。 |
| 并列种子的 ID 排序 | 某些种子键把 ID 转为字符串，可能出现 10 在 2 前面的顺序。顺序确定，但不等于数值升序；本轮为保持候选路径不改这一规则。 |
| 时间限制与未完成域 | 预处理/官方调用允许返回后再检查时限；总搜索时间不是整个组合的硬超时。某轮没有接受改善即结束，局部域可能仍因时间或评价预算未搜完。需同时看 `search_status` 和域的 `stop_reason`。 |
| 限时运行的等价性 | 固定候选、相同预算且排除真实时间截断时检查判断与路径等价。实现提速、服务器并发或加长预算都可能改变截止前探索位置，不承诺实际限时最终方案逐字一致。 |
