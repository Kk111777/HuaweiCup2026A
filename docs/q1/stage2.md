# 第一问第二版模型：基于严格剪枝的多原则候选方案分层改进策略

第二版完整模型由第一版 TaskGrowth 基座与本策略共同构成；`stage2` 只是其改进阶段，不是另一个基座。第三版见 [unified.md](unified.md)，两者从同一基座发展，分别保留自己的搜索与评价规则。

程序读取第一阶段最终选中的**一份**完整方案，从五类实际执行现象产生候选，先调整编排，再调整切法，最后在小区域内联合枚举。第一次输入核验和最终落盘复评均调用完整官方多核评价。初始化算法、官方调度算法及原始实验产物不参与修改。

## 1. 入口、配置与输出

Python 3.12 及以上，核心程序仅依赖标准库。先按主 README 准备 `official/data/`。基座初值可由 `python tools/reference_problem1.py solve ... --output-root outputs/q1_v1` 生成，或读取已有 V1 归档。

```powershell
# 单例；核心数从方案的 core_schedules 长度读取，必须为 2--5
python src/solve_problem1.py improve official/data/case_001.json --initial-plan outputs/q1_v1/case_001/N2/plan.json

# 阶段一目录或包含 cases/case_XXX.zip 的百例归档，默认按用例串行
python src/solve_problem1.py improve-batch --initial-root path/to/archive --cases all --cores 2 3 4 5 --jobs 1 --resume

# 有限验证，不改变默认搜索参数文件
python src/solve_problem1.py improve-batch --initial-root path/to/archive --cases case_086 --cores 2 5 --search-seconds 120 --output-root outputs/q1_stage2_check

# 自选参数；命令行秒数及域评价次数覆盖文件中的同名项
python src/solve_problem1.py improve-batch --initial-root path/to/archive --cases case_001 --cores 2 --search-config configs/q1/stage2.json
```

批量支持 `--data-dir`，两种入口均支持 `--config`、`--output-root`、`--baseline-archive`。默认单核参考来自 `results/problem_1_singlecore/`，核验输入、配置和官方代码后复用；显式 `--recompute-baseline` 才重新计算，每例只算一次，供所有核数使用。默认配置路径在输入数据目录，默认输出和基线定位仓库，与当前工作目录无关。自定义小图需要提供自己的基线归档，或显式重算基线。

默认参数见 [stage2.json](../../configs/q1/stage2.json)：

| 参数 | 值 | 含义 |
|---|---:|---|
| `search_seconds` | 1800 | 每例每核数搜索秒数，含诊断与构造 |
| `layer_shares` | 0.2, 0.3, 0.5 | 每轮剩余时间的三层份额，前层余量顺延 |
| `region_seconds` | 120 | 单个域的搜索秒数，仍受当前层截止时刻限制 |
| `region_evaluations` | 256 | 单域兼容预算计数上限：原四项缓存命中不计，二级缓存命中仍计一次 |
| `seeds_per_principle` | 8 | 每类原则的种子数上限 |
| `partners_per_seed` | 8 | 检测器的搭档、候选切口短名单上限 |
| `max_region_tasks` | 3 | 区域中原 Task 数上限，含夹心 Task |
| `max_fragments` | 6 | 每个域的基本片段或固定新 Task 数上限 |
| `ddr_endpoints` | 12 | DDR 区间检查的端点数上限 |
| `pruning` | partial, b0, b1, ddr | 可分别关闭，用于剪枝消融与正确性对照 |

截止后不启动下一次核内展开或完整评价；正在执行的官方函数允许返回。**这是搜索预算，不是总墙钟的硬超时**。初始核验、最终独立复评和写盘另计。`--jobs` 为用例进程数，默认 1；同一用例的各核数顺序执行，兼容 Windows spawn 和 Linux。

默认产物：

```text
outputs/q1_stage2/
  summary.json / summary.csv
  case_001/N2/
    plan.json                 只有两个提交字段
    result.json / result.log / trace.json
    initial_result.json       本次重新评价的初值
    optimization.json         参数、种子、动作/域、剪枝、接受历史、统计
    metrics.json / provenance.json
    events.jsonl / official.log
    checkpoint_plan.json      最近一次接受的方案；未发生接受时不产生
    checkpoint.json
    complete.json             独立复评一致及产物哈希标记
```

`summary` 的平均加速比为逐例单核时间/当前时间的算术平均，并显示完成数、预期数和部分结果状态。`complete` 表示产物已验证；其中的 `search_status` 单独描述是否搜索完成。失败写 `attempt_failure.json`，其他用例继续；存在失败则批处理返回非零。程序错误不会被包装成调度不可行。

`--resume` 只跳过来源指纹一致且全部产物哈希有效的已验收输出，即使其搜索状态是 `INCOMPLETE`。指纹包含原图、配置、阶段一选中记录/方案、公共基线、全部自有依赖代码、官方代码、Python 和搜索参数。不同指纹或残缺输出拒绝覆盖，要求新输出目录。中断后可把 `checkpoint_plan.json` 作为新一轮 `--initial-plan`；首版不恢复分支栈。

阶段一 ZIP 逐文件流式核验 SHA-256，Trace 只参与校验，不整体解压。核对其原图、配置、官方代码、原始运行指纹、核心数、方案和指标；跨机器路径不参与身份判断。独立方案没有归档评价时，仍先执行本次官方初值评价。

Python 接口：

```python
from q1 import official
from q1.stage2 import improve, SearchOptions

answer = improve(graph, initial_plan, settings,
                 options=SearchOptions(search_seconds=60), progress=on_event)
# answer.plan / evaluation / initial_evaluation / status / history / records / statistics
```

此接口不写文件，不调用第一阶段初始化；`expected_initial` 可传已核验的归档评价，在搜索前检查完整结果一致。运行入口负责归档接入、持久化和最终未适配官方复评。

## 2. 状态、变量与接受规则

原图为操作—张量 DAG。以下量都从原图、题目配置或本次官方结果读取。

| 符号 | 定义 | 代码 |
|---|---|---|
| \(O_c\) | 除 COPY_IN/OUT 外的计算操作集合 | `Context.index.ids` |
| \(c_v\) | 操作输入周期；官方实际最短持续时间取 \(\bar c_v=\max(1,c_v)\) | `GraphIndex.cycles`, `Context.measure` |
| \(s_t,b\) | 张量字节数、总 DDR 带宽 bytes/cycle | `Tensor.size`, `Settings.bandwidth` |
| \(q_t\) | 一次独占搬运工作量 \(\max(1,\lceil s_t/b\rceil)\)，与官方一致 | `Tensor.copy_cycles` |
| \(\Pi=(g,\pi)\) | 操作到 Task 的映射及各核心 Task 列表 | `PlanState.mapping/orders` |
| \(S_j,k_j\) | Task 的操作集合、所属核心 | `PlanState.nodes/core` |
| \(\delta_s,\delta_c\) | 同核相邻 Task 等待、跨核前驱等待 | `Settings.same_core_wait/cross_core_wait` |
| \(Z(\Pi)\) | 边界构造、Step1/2/3 和完整多核模拟结果 | `Evaluator.evaluate` |
| \(s_j,f_j\) | Task 的实际开始、结束周期 | `per_core_timeline.tasks` |
| \(s_o,e_o\) | 扩展操作实际开始、结束周期 | `per_core_timeline.ops` |
| \(T(\Pi)\) | 官方总体时间 | `result.makespan` |
| \(D(\Pi)\) | 官方总额外搬运字节数 | `data_movement_bytes.added_copy_bytes` |

扩展操作必须用 `(task_id, op_id)` 识别；不同 Task 可能使用相同新增操作编号。共享张量判断使用原始逻辑张量 ID，缓存位置严格采用 `pos`，每个 Task 的缓存状态重新建立。

对完整评价后的候选 \(\Pi'\)，只接受

\[
(T(\Pi'),D(\Pi'))<_{\rm lex}(T(\Pi),D(\Pi)). \tag{S1}
\]

等价地，\(\Delta=T(\Pi)-T(\Pi')>0\) 时接受；若 \(\Delta=0\)，只有 \(D(\Pi')<D(\Pi)\) 才接受；两项相同拒绝。因此已接受序列的总时间单调不增。构造评分、核内 Step3 时间和旧实测时刻都不能替代候选的完整模拟。

第一、二层比较该层预算内的所有已评价候选，保存最好者；若预算前穷尽，得到规定候选集的最好者。第三层逐区域搜索，每个区域在其预算内保存最好者；出现改善即接受，不继续比较后续区域。任何接受都回到第一层，使用刚得到的完整评价重新诊断。相同方案在缓存内时复用精确结果；两级缓存均未命中时仍会重新模拟。

`history` 记录前后目标、`delta_cycles`、`delta_added_bytes`、完整方案及哈希。初始/最终保护检查再次保证 S1，不把“时间变差但搬运减少”接受为改善。

## 3. 工作量与边界

令 \(I(S)\) 为集合内操作使用、但生产者不在集合内的张量；原始输入没有计算生产者。令 \(O(S)\) 为集合内生产、且有集合外消费者或需要最终写出的张量。张量在一个集合的输入/输出边界分别只计一次，多消费者不能重复计同一读。

\[
W_p(S)=\sum_{v\in S:\,\operatorname{pipe}(v)=p}\bar c_v,
\qquad p\in\{M,V\}, \tag{S2}
\]
\[
Q(S)=\sum_{t\in I(S)}q_t+\sum_{t\in O(S)}q_t,
\quad C(S)=\sum_{t\in I(S)}s_t+\sum_{t\in O(S)}s_t. \tag{S3}
\]

\(L^{\rm int}(S)\) 是官方边界构造**实际保留**的内部计算依赖上的最长计算路径。用于 Task 可行性的索引保留经过原始 COPY 收缩的依赖；用于时间下界时，两者必须区分。某些手工图中“计算→COPY→计算”的同 Task 收缩边被官方边界构造移除，因此不能将它无条件计入 \(L^{\rm int}\)。测试包含该反例。

## 4. 五类诊断与具体动作

五类原则分别排序，没有混合权重总分。同类不同检测器轮流取种子，五类的入选队列再轮流输出。指标并列用 Task、操作、张量 ID 和稳定哈希确定顺序。每类最多 8 个种子；搭档或切口短名单最多 8。进入短名单前的过滤量记为 `prefilter_unsearched`，已构造但未选种子量记为 `not_selected`，均不是严格剪枝。

### 4.1 数据局部性

共享原始输入 \(t\) 被 \(m_t\) 个 Task 使用时，重复读取参考量为 \((m_t-1)q_t\)。按重复量、字节数、张量 ID 排序，候选搭档再按合并节省与当前开始时刻接近程度选择。

两 Task 的边界搬运节省为

\[
G_{ij}=Q(S_i)+Q(S_j)-Q(S_i\cup S_j). \tag{S4}
\]

实现用输入交集、生产/消费交叉及外部消费者计数直接计算相同的差值。外部仍有消费者或最终输出要求时，不能删掉输出写回。局部性候选包括合并，以及把消费者及其必要内部前驱转移到搭档。

实际 spill 的工作量采用官方 `spill_records`：

\[
Q_{\rm spill}=\sum_h q_h(1+\mathbf1[\text{本次实际写回}]). \tag{S5}
\]

已存在有效 DDR 副本时，换出不必再次传数据，不能机械计成双倍。切口取官方 Step1 中再次使用之前的计算前段，补全内部前驱；按新增边界工作量较小优先。正常 spill 是诊断依据，不是不可行性。

### 4.2 管道协同

互补量

\[
K_{ij}=\max_pW_p(S_i)+\max_pW_p(S_j)
       -\max_p\{W_p(S_i)+W_p(S_j)\}. \tag{S6}
\]

它表示把偏 M、偏 V 的工作放在同一 Task 可能节省的计算占用，仅用于候选排序。另记录当前 M/V 实际区间交叠 \(\Omega_j\)，以 \(\min(W_M,W_V)-\Omega_j\) 识别重叠不足。汇合点的 M/V 前驱若彼此不能到达，则产生独立分支种子；闭包可能相交，必须在第三层细分，公共前驱不能复制。

动作包括互补合并、前段/分支切分及域内重组。依赖、等待与 DDR 可能抵消互补收益，最终仍按 S1。

### 4.3 Task 边界时序

对跨核依赖 \(i\to j\)，令 \(c_{ij}\) 为需要交付的全部张量写好和直接控制前驱完成的最晚时刻，\(h_{ij}=(f_i-c_{ij})_+\)。令 \(x=f_i+\delta_c\)，\(y\) 为排除 \(i\) 后其他跨核前驱及同核前一 Task 的最晚约束，则释放时序种子量为

\[
R_{ij}=\min\{h_{ij},(x-y)_+\}. \tag{S7}
\]

切出交付操作及其必要内部前驱，可能免去原 Task 尾部对后继的阻塞。多个前驱并列最晚时，单个释放未必有效，程序额外生成并列前驱与后继的联合种子；超出三 Task 域上限如实记未搜索。

对于迟到输入，取最晚一个或两个到达层的前驱，找到 Task 中受其影响的操作及后继闭包，其补集 \(A\) 是不依赖这些输入的前段。用当前其余前驱和同核前项估计 \(r_A\)，排序量为

\[
\min\{(s_j-r_A)_+,d_A^{(0)}\}. \tag{S8}
\]

这些时刻来自旧方案，只用于诊断，不能进入剪枝下界。

### 4.4 DDR 竞争

对实际占用 DDR 的操作 \(o\)，令独占工作量为 \(q_o\)，记录

\[
\ell_o=(e_o-s_o)-q_o,\qquad
\sigma_o=T-e_o-h_o. \tag{S9}
\]

\(\ell_o\) 是实际搬运慢于独占服务的周期，\(h_o\) 是固定执行关系中从该操作完成到总体结束的必要尾部长度。按竞争延长较大、余量较小、工作量较大排序，搭档取 COPY 区间重叠较多的其他 Task。

候选包括前后移动、迁核；对竞争搭档中早读晚用的 COPY_IN，沿官方扩展张量映射找到真实消费者，若首次使用晚于 COPY 完成且有独立前段，则切出不依赖该数据的计算。spill 重命名后的张量不能直接当成原始张量匹配。

### 4.5 多核负载

记录核心结束 \(F_k=\max_{j:k_j=k}f_j\)、管道工作 \(W_{kp}=\sum_{j:k_j=k}W_p(S_j)\)、Task 占用率 \(u_k=\sum_j(f_j-s_j)/T\)。负载种子依次按核心结束、最大管道工作、Task 持续时间、后续计算路径排序；这些是不同的可解释量，不求加权和。

大 Task 的切口为官方 Step1 计算序列中达到主导管道一半工作量的真前缀，再补全前驱；只有最后操作才能达到一半时，没有这种真前缀，不凭空生成切口。动作是迁移、重排和拆分。

## 5. 三层邻域与精确性范围

### 第一层：Task 编排

对选中 Task \(j\)，先从核心列表移除它，将原前后项重新接续。计算**包含所有其他核心顺序**的先后关系中 \(j\) 的祖先 \(A_j\)、后继 \(D_j\)。目标核心剩余列表为 \((v_0,\dots,v_{m-1})\)，合法插入间隙编号 \(b\in[0,m]\) 满足

\[
\max(\{r+1:v_r\in A_j\}\cup\{0\})
\le b\le
\min(\{r:v_r\in D_j\}\cup\{m\}). \tag{S10}
\]

枚举所有核心的全部合法间隙，并检查同一种子搭档的同时交换；交换直接检查最终方案，不要求某个虚构的中间单步迁移可行。旧时刻与局部时间只排序候选。

### 第二层：固定切法后联合编排

生成两 Task 合并、内部前驱闭包拆分，以及向搭档转移该闭包或其补集。切法确定后，**不调用第一阶段列表分配**，直接在记录的窗口和允许核心中枚举新 Task 的核心归属及合法局部排列。

### 第三层：片段重划

在选中 Task 与必要路径/夹心 Task 构成的区域内，当前 Task 边界和诊断切口共同细分成互不相交的非空片段。加入切口若会超过 6 片段，记录未使用的切口；固定后的域再完整枚举。

规范标签用 restricted-growth 顺序：处理下一片段时，可放入任何已有组或新建下一个组。每个片段集合划分恰好生成一次。该规范只消除组标签重复，**不固定一条全局拓扑序限制排列**。随后枚举允许核心的所有赋值，再枚举各窗口满足执行先后的全部排列。

域必须明确记录：原 Task 集合、片段、固定/重划模式、核心窗口、窗口左右锚点、允许核心及来源种子。同核选中项之间的夹心 Task 一并纳入；总数超过 3 则不搜索。允许核心包括原核心，再加入一个域外最轻核心（最大管道工作、结束时刻、编号依次较小），其空窗口放在当前区域最早开始时刻之前已完成的 Task 之后。

域外操作成员、核心和相对顺序不变；实际时间仍然通过全图评价重算。未改 Task 保留编号；新集合等于旧集合则复用旧 ID；其他新集合按最小操作 ID 排序，领取最小未用非负编号。官方事件排序可能与 ID 有关，因此不跨任意重编号宣称等价或复用。

没有预算截断时，限定域内分支定界与完整枚举具有相同最优目标：规范标签遍历所有集合划分，核心赋值和各核排列覆盖所有允许编排；不可逆循环和下界排除均不能删除严格改善的补全。该结论不涉及域外重新分组、其他窗口、未选种子或未采用切口。

## 6. 严格剪枝

### 6.1 结构与基础下界

先检查每个计算操作覆盖一次、每个 Task 安排一次，以及计算依赖和同核列表关系合并后无循环。一个 Task 在结束后才能释放另一个依赖 Task，循环意味着互相等待，必须拒绝。

单 Task 必需时间

\[
d_j^{(0)}=\max\{W_M(S_j),W_V(S_j),L^{\rm int}(S_j),Q(S_j)\}. \tag{S11}
\]

四者分别是 M 管道、V 管道、内部依赖路径和该 Task 的共享 DDR 必需工作，各自必须被真实执行容纳。不会把两个计算管道简单相加。

在 Task 统一关系上，跨核依赖边等待 \(\delta_c\)，同核相邻边等待 \(\delta_s\)，其他同核依赖为 0；重合边取最大值而非重复相加。记此等待为 \(w_{ij}\)，则

\[
E_j^{(0)}=d_j^{(0)}+\max_{i\to j}(E_i^{(0)}+w_{ij}),
\quad B_0=\max\{\max_jE_j^{(0)},\sum_jQ(S_j)\}, \tag{S12}
\]
\[
D_0=\sum_j C(S_j)-D_{\rm original}. \tag{S13}
\]

\(D_{\rm original}\) 是官方定义的原图 COPY 字节数。未计算的 spill 不可能减少已必需的边界搬运。实现空前驱最大值为 0。

### 6.2 官方展开与固定执行关系下界

调用原版边界构造、Step1、Step2 spill、Step3，保留官方扩展依赖和缓存依赖。建立操作开始/完成关系，加入**各 Pipe 内的相邻次序**、Task 开始/结束以及 S12 的 Task 等待；不将跨 Pipe 的整个序列强制串行。

扩展操作 \(o\) 的独占时长 \(p_o\) 由官方 `_op_duration` 计算。关系边必要间隔记为 \(w_{uv}\)，最长路径递推：

\[
r_v=\max_{u\to v}(r_u+p_u+w_{uv}),\qquad
h_u=\max_{u\to v}(w_{uv}+p_v+h_v). \tag{S14}
\]

\(r_v\) 是最早开始下界，\(h_u\) 是从 \(u\) 完成到全局结束的必需尾部。Task 开始到结束另加入该 Task 总 DDR 工作量及 \(d_j^{(0)}\) 的必要间隔。全局终点为 \(z\)，实际 DDR 操作集合为 \(C_{\rm DDR}\)，则

\[
B_1=\max\{B_0,r_z,\sum_{o\in C_{\rm DDR}}p_o\}. \tag{S15}
\]

展开后搬运量为官方边界/ spill 构造给出的**精确字节数**。所有新增关系均是当前完整候选的必需关系，每个独占时长在共享 DDR 下只能延长；故 \(B_0\le B_1\le T\)。虚拟缓存惩罚、诊断分数、旧实际时间不出现在这些下界中。

对当前最好目标门槛 \((U,V_*)\)，只有

\[
B>U\quad\text{或}\quad B=U\ \land\ D_{\rm lower}\ge V_* \tag{S16}
\]

才由下界排除。`B=U` 但搬运仍可能变少时必须保留。

### 6.3 DDR 区间容量

若候选要在 \(U\) 内完成，每个搬运需要 \(q_o=p_o\) 单位 DDR 服务，可用窗口必须在 \([r_o,d_o]\)，其中 \(d_o=U-h_o\)。若 \(r_o+q_o>d_o\)，直接不可能。对任意检查区间 \([a,b]\)，该 COPY 在区间内最少必须消耗

\[
m_o(a,b)=\max\{0,q_o-(a-r_o)_+-(d_o-b)_+\}. \tag{S17}
\]

由于所有核心共享总带宽，若 \(\sum_o m_o(a,b)>b-a\)，便不可能在 \(U\) 内完成。端点候选来自所有 \(r_o,d_o\) 以及 \(0,U\)；超过 12 时按排序位置均匀抽取。只检查部分区间会漏掉一些排除机会，不会把检查通过当作可行性证明。

### 6.4 部分分支

尚未分组的片段不建立临时 Task；它们将来可加入已有组，因而不能用这种临时图中的环剪掉整个分支。程序只使用已固定不同组之间的依赖及域外固定顺序判环。

部分分支下界包括全图各计算管道工作除以核数、官方保留的计算路径、已确定核心的管道工作、已知组的工作及已强制发生的边界搬运。只有生产者/消费者标签已确定且不同，才加入对应写回/读取；未知生产者不猜测。已知组的依赖路径可递推，跨核等待只有两端核心都固定且不同时才加入。编号、未知核心、可变化边界及虚拟缓存均不用于强剪枝。

`B1` 和 DDR 区间仅在完整叶子执行。排除记录的 `scope` 明确为 `complete_plan` 或 `branch_completions`。后者同时保存当前规范标签或已分配核心，以便复核它排除了哪些补全。

## 7. 官方适配、缓存与状态

`evaluate.isolated` 用原函数的代码对象、默认参数和复制的全局命名空间建立隔离调用，替换其中一个构造调用以收集 Step2 或提供已准备 Task；不修改原模块全局变量，不重写模拟器。全局带宽、等待、事件调度仍执行原版 `evaluate_scene_a` 函数体。

核内展开缓存键为原图、配置、官方代码、完整操作分组及 Task ID；最多保留 2 个模板。只迁核/重排可复用。模拟共享只读的算子、张量、依赖与 Pipe 顺序，每次独立建立 Task 外层对象、核分配、前驱集合和执行游标；结果与缓存之间保持可变对象隔离。不同划分、不同编号不猜测复用。每个 Context 另保留至多两个分区的规范序列化、结构索引及 B1 静态模板；排程相关连接和原下界递推每次重算。

完整评价键再包含全部核心列表。原四项 LRU 的查询位置和淘汰规则保留；只有通过原剪枝、即将模拟时才查询二级结果缓存。两级共用当前 Evaluator 自行生成的不可变序列化字节，避免重复保存完整结果对象；二级按 LRU 管理，载荷上限 128 MiB，单项超限不保存，不读取外部序列化文件。命中后恢复独立对象并按原流程更新四项 LRU。

`evaluations` / `official_evaluations` 继续记录实际成功模拟次数；`budget_evaluations` 记录旧实现原本会消耗的成功评价名额，包含二级命中，原四项缓存命中不计。局部域按后者截断，失败调用仍沿用旧行为而不计数。`secondary_hits`、`secondary_bytes`、`secondary_evictions` 分别报告二级命中、当前载荷字节和淘汰次数。固定候选和无时间截断时保持原预算行为；真实限时运行可因加速搜索到不同位置。

| 状态 | 解释 |
|---|---|
| `EXACT` | 完整方案已官方评价，或精确缓存命中 |
| `PRUNED` | 结构或严格下界排除了记录范围 |
| `INVALID` | 完整方案出现明确不可行的官方调度错误或循环 |
| `INCOMPLETE` | 时间、评价次数、官方迭代上限等导致未完成 |
| `OPTIMAL_IN_DOMAIN` | 当前记录的限定域穷尽，最好方案达到域内最优 |
| `NO_IMPROVEMENT_IN_DOMAIN` | 限定域穷尽，不能严格改善给定外部门槛 |
| `NEIGHBORHOOD_EXHAUSTED` | 本轮生成的规定候选/域已结束且无改善；不涵盖未选种子/超规模域 |

`LAYER_IMPROVED` 可能来自预算内最好方案；必须同时看 `candidate_set_exhausted` 和各域状态。第三层提前接受时后续区域未比较，不能把整层记为穷尽。官方 `max_iter` 是资源限制，记未完成；输入/程序异常向上报告，不能当作可行性修补。
